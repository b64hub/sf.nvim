## Assumption corrections (read before Step 1)

**(A) `Api.get_session` signature.** Doc said "just add `:set_org(alias)`
when passed" — true, but naively changing `get_session(cb)` to
`get_session(alias, cb)` breaks 8 existing positional call sites in
`debug.lua`. Fix: keep arity, dispatch on `type(first_arg) == "function"` to
tell old-form from new-form calls. Zero call-site churn. (Step 8.)

**(B) `cmd_builder:set_org` works but captures `util.target_org` at
`new()`-time.** `set_org(alias)` does correctly override it, but any
dashboard code building a command for a non-target org must always call
`set_org(record.alias)` explicitly — never rely on the target-org fallback.

**(C) `isDefaultDevHubUsername`** is returned by `sf org list --json` (not
stripped by `--skip-connection-status`) but never read into
`helpers.orgs` today. Genuine one-line add, confirmed safe. (Step 2.)

**(D) AGENTS.md naming rule applies retroactively to touched files.**
`org_explorer.lua`'s existing `M`/`H`/`B`/`S` single-letter tables must be
renamed whole-file as part of Step 1, since that step edits the file anyway.

**(E) `/limits` endpoint requires the bearer token** — the design doc's
"unauthenticated-by-token" phrasing for the limits view (Step 12) was
imprecise; it's still just one more `curl` call, no new dependency.

## Steps

### Phase 1 — Extraction (no behaviour change)
1. Extract `render_list_lines`, `highlight_for`, `pad`,
   `render_detail_lines`, `paint`, `fetch_org_display`,
   `SPINNER_FRAMES`/`REDACT_KEYS`/`DETAIL_KEY_ORDER` out of
   `org_explorer.lua` into new `lua/sf/ui/org_view.lua`. Rename
   `org_explorer.lua`'s short identifiers whole-file per AGENTS.md.
   `org_explorer.pick`'s name/behaviour is unchanged (3 callers in
   `org.lua`). Test: `tests/test_org_view.lua` (mini.test, follow
   `tests/test_org.lua`'s child-neovim pattern) covering the pure
   functions only.
2. Add `is_default_devhub` to the record in `helpers.store_orgs`
   (`org.lua`). Add `org_view.days_until(date_string, now_timestamp)` ->
   `"14d"|"6d"|"today"|"expired"|nil`, injectable clock for
   determinism. Update `render_list_lines`: `●` default target org, `◆`
   default devhub, `◈` both. Extend `tests/test_org_view.lua`.

### Phase 2 — Dashboard shell
3. `Layout.float_geometry_pair(opts)` in `layout.lua` — splits the
   existing `float_geometry` box left/right (`left_ratio` default 0.3),
   accounting for both floats' own borders so they never overlap.
   Rename `M` -> `layout` in this file. Test: `tests/test_layout.lua`,
   pure geometry math.
4. New `lua/sf/ui/org_dashboard.lua`: `org_dashboard.open(records, opts)`.
   Two floats from `float_geometry_pair`; left renders the org list
   (`org_view.render_list_lines`), right hardcoded to the details view via
   `org_view.fetch_org_display`/`render_detail_lines`. Reuse the proven
   `generation` counter, spinner timer, and `winhl` string from
   `org_explorer.lua` verbatim. `CursorMoved` on the left re-renders the
   right pane; `q`/`<Esc>` closes both. Test: `tests/test_org_dashboard.lua`
   with stubbed fetch (no real CLI call).

### Phase 3 — View registry
5. New `lua/sf/ui/dashboard_views.lua`: array of
   `{ id, key, label, fetch(record, cb), render(record, data), action(record, api) }`
   descriptors. Generic `show_view(view_id)` controller in
   `org_dashboard.lua` replaces Step 4's hardcoded details view. Footer
   hint string generated from the registry. Test: extend
   `tests/test_org_dashboard.lua` with a fake view descriptor (cache-hit
   behaviour, footer contains every key).
6. Org status view: new `lua/sf/sub/org_status.lua` —
   `org_status.fetch(session, cb)` (SOQL `Organization.InstanceName` via
   `Api.query_std`, then unauthenticated GET to
   `https://api.status.salesforce.com/v1/instances/<name>/status` via
   `Api.curl_json`), plus pure `parse_instance_status(decoded)`. Test:
   `tests/test_org_status.lua` against JSON fixtures, no network.
7. Action entries: set-local-default, set-global-default, open-org.
   Promote `helpers.write_target_org_to_config`/`open_org` onto the public
   `Org` table as thin wrappers (`Org.set_target_org_to`, `Org.open_org`) —
   do not call `Org.__test.*` from production code. Re-paint left pane
   after a default change (`mark_default` already mutates in place).
   Test: extend `tests/test_org.lua` for the new public wrappers.

### Phase 4 — Alias-scoped session
8. `Api.get_session(alias_or_callback, maybe_callback)` in `rest_api.lua`
   — backwards-compatible optional leading alias (see correction A).
   Rename `M`/`U`/`B` whole-file per AGENTS.md. Test:
   `tests/test_rest_api.lua`, stubbing `util.silent_system_call` to assert
   the built command.
9. Trace-flags view (SOQL on `TraceFlag`, remaining-minutes formatter —
   don't promote `debug.lua`'s private datetime parser, write a small
   local pure helper instead) + enable-logging action. Requires
   `Debug.enable_replay_logging` to accept an optional `opts.alias` that
   flows into the now-alias-aware `Api.get_session`. Test: pure
   remaining-minutes formatter only.

### Phase 5 — Native log list
10. `Org.list_org_logs(alias, cb)` + pure `helpers.parse_log_list(stdout)`
    extracted out of `helpers.pick_org_log`'s inline JSON handling;
    `pick_org_log` calls the same helper (fzf-lua behaviour unchanged).
    Test: `parse_log_list` against a recorded `apex list log --json`
    fixture.
11. Log list view in `dashboard_views.lua`: renders `list_org_logs`
    output, `f` prompts a substring filter (`filter_logs(logs, query)`,
    pure + tested), native `/` search works for free, `<CR>` downloads via
    existing `Org.download_log`.

### Phase 6 — Bounced-in extras
12. Org limits view: one `curl` GET to `.../limits` with the bearer
    token via `Api.curl_json`; pure `format_limits(decoded)` (used-percent,
    zero-`Max` guard, interesting-first sort). Tested against a fixture.
13. Installed packages view: one Tooling query on
    `InstalledSubscriberPackage`; pure row-flattener + test. Independent of
    Step 12, can run in parallel once Step 5 lands.
14. Manual `r` refresh key: clears cache, bumps `generation`, re-runs
    `Org.fetch_org_list`. Requires an optional `on_done` callback on
    `fetch_org_list`/`fetch_and_store_orgs` (today's `jobstart` has no
    completion signal) — additive, defaults to nil = unchanged behaviour.
    Explicitly no timer/polling. Test: callback fires; `r` empties cache.
15. Public surface: `Sf.open_org_dashboard` in `init.lua` (with doc-comment
    for `:h sf.nvim`), `<leader>sfg` keymap, `:SF org dashboard` command.
    Guard on empty `helpers.orgs` (same message the existing pickers use).

## Batching for workers

Land 1–2 together (extraction must be atomic or the picker renders
inconsistently). Then 3–4, 5–7, 8–9, 10–11, 12–14, 15 as separate handoffs.
12 and 13 can run in parallel once 5 exists. Every step must leave `make
test` green and the existing modal picker (`org_explorer.pick`) behaviourally
untouched.

Three points flagged for explicit confirmation before landing (each widens
an existing function's contract, additive/backwards-compatible in all
cases): promoting `helpers.open_org`/`write_target_org_to_config` onto
`Org` (step 7), `opts.alias` on `Debug.enable_replay_logging` (step 9),
`on_done` on `fetch_org_list` (step 14).
